# Agent instructions export (#19)

POII can hand its current decisions to a coding agent working in another repository as `AGENTS.md` and `CLAUDE.md`. The files are a rebuildable projection of the current-decisions view (ADR-0001): they are generated, never edited, and can be produced again at any time. Routes: [api.md, "Agent instructions export (#19)"](api.md). Code: `apps/api/src/domain/agent-instructions.ts` (pure rendering) and `apps/api/src/modules/exports/agent-instructions.*.ts` (loading, storage, routes).

## What goes in

Confirmed records of kind `decision` or `requirement` that have an approval and no confirmed successor: the rule of `GET /v1/decisions/current` (which shows decisions only), with requirements added. Superseded records, candidates, rejected records, facts and questions are left out. A superseded record's id appears only on its successor's `Replaces:` line.

## Format (`poii.agent-instructions` v1)

Each file is a header, then the body.

- **Header**: a "generated by POII, do not edit by hand" comment; the title; `File: AGENTS.md` (or `CLAUDE.md`); the workspace name and id, the generation time and the export run id; the content hash; the format and version. The two files differ in the `File:` line only.
- **Body**: starts with the line `<!-- poii:body -->`, then a short "how to read this file" list, then `## Current decisions and requirements (N)` with one `### n. Title` section per record:
  - `Record` id, kind and lifecycle status; effective and observed time, each with its status (`known`, `unknown`, `not_applicable`, `conflicting`); the approval; `Replaces:` when the record replaced another.
  - `Statement:` the record's body, as a blockquote.
  - For each evidence span (primary first, then by revision and offset): the excerpt as a blockquote, and a citation line.

A citation line names the record id, the source title and id, the revision id, the start and end character offsets (UTF-16, as everywhere in POII) with the lines, the excerpt SHA-256, the anchor result (`exact`, `moved`, `lost`), and the approval as authority and time with the approval id. Approvers are named by authority (`owner`, `delegated`), not by display name, because the files usually land in another repository. Evidence from a deleted source is cited as unavailable with the original source id and no excerpt; evidence from an archived source is cited without its excerpt, as in context packs.

Statements and excerpts are always blockquoted: text from sources is data, never instructions (BUILD-BASELINE §1).

## Ordering and determinism

Records are ordered by effective time ascending (records without a known effective time last), then title, then id, comparing strings by code unit so the order never depends on the server's locale. The body contains no run id, no generation time and no staleness label, and uses LF line ends only. `contentSha256` is the SHA-256 of the body's UTF-8 bytes from the `<!-- poii:body -->` line to the end of the file, so the same current decisions always give the same hash. To verify a file: take everything from the line `<!-- poii:body -->` on and hash it.

## Never-send content

A record is withheld when its stored `aiAllowed` flag is false or any live source it cites has `aiAllowed = false`. This mirrors the rule in `apps/api/src/ai/disclosure.ts` (stored flag plus every live cited source); that module is not reused because it reads the database and refuses on the first never-send item, while an export has to list every record. A withheld record keeps its place in the order and shows only its title, kind and record id with "content withheld: never-send source". Its statement, excerpts, source titles and source ids are not written. The run's `withheld` list names it. The rule applies whoever exports.

## Re-exporting

Change decisions in POII (confirm, supersede, set status), then export again: in the web app, Export → Export agent instructions; or `POST /v1/exports/agent-instructions` with `{}`. Each export is a new `export_run`; old runs stay downloadable. Copy the new `AGENTS.md` or `CLAUDE.md` over the file in the other repository; if `contentSha256` is unchanged, nothing changed.

## Storage and permissions

The two files and the run document are written through the storage port (`exports/<run id>/AGENTS.md`, `exports/<run id>/CLAUDE.md`, `exports/<run id>.json`). The `export_run` row uses `kind = context_pack` (the database enum has no other value without a migration) and is recognised by `manifest.format = "poii.agent-instructions"`. Creating and reading an export needs the `read` capability, the same rule as context packs, so a read-scoped owner token can export. No setting is needed.
